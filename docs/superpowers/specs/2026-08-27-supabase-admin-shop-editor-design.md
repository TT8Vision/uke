# Supabase-Backed Admin Shop Editor — Design

**Date:** 2026-08-27
**Status:** Approved for planning
**Repo:** `uke` (TT8Vision static client site — `uk-emporium`)

## Summary

Make the Supabase **UKE** project (`dyifpssjebmkvpdoiyas`) the live source of
truth for the shop catalogue. Public pages read products live from Supabase.
Admins sign in with a Supabase magic-link and edit products **inline on the real
site**; writes are enforced admin-only by Row Level Security. Because every page
reads from the one table, edits appear on home, shop, and category pages on the
next load — no rebuild, no git commit.

This replaces the git-based editing model (Decap CMS + Netlify Identity) as the
*live* editing path. The old Decap editor is left in place but documented as
deprecated.

## Decisions (from brainstorming)

| Decision | Choice |
|---|---|
| Supabase role | **Live source of truth** for shop data |
| Editor UX | **Inline** editing on the real shop/category/home pages |
| Edit scope (fields) | **All card fields** — price, sale price, brand, name, volume, badge, stock, "new" flag, image |
| Add / delete products | **Full management** — admins can add, edit, and delete |
| Admin access | **Invite-only**; no public sign-up. Admins managed in Supabase |
| Login method | **Magic-link email** (passwordless) |
| Old Decap `/admin` | **Left in place, marked deprecated** |

## Non-goals

- No customer/public accounts (the existing `my-account.html` is untouched).
- No editing of featured lists or the promo banner (stay as static JSON).
- No removal of the Decap CMS in this work.
- No password auth, no OAuth providers.

## Current architecture (before)

- Static HTML site (Netlify). Shop reads `data/products.json`.
- `data/products.json` is a build artifact generated by `npm run build:catalogue`
  from `data/products/*.json` (868 files, the current source of truth).
- `js/render-products.js` centralises loading: `Catalogue.load()` does
  `fetch('data/products.json')` and every page renders from that.
- Editing today: Decap CMS at `/admin`, gated by Netlify Identity, commits to git;
  Netlify rebuilds `products.json`.

## Target architecture (after)

```
                 ┌─────────────────────────┐
   public read   │  Supabase: products     │   admin write (RLS: is_admin())
  ◄──────────────┤  (single source of truth)├──────────────►
                 └─────────────────────────┘
        ▲                                          ▲
        │ supabase-js (anon key, RLS public-read)  │ supabase-js (admin session)
        │                                          │
  ┌───────────────┐                        ┌────────────────────┐
  │ every page     │                        │ admin bar + inline │
  │ Catalogue.load │                        │ editor overlay     │
  └───────────────┘                        └────────────────────┘
```

## Data model

### `public.products`

One row per product. Column names are snake_case in the DB; the client maps them
to the shape `render-products.js` already uses.

| Column | Type | Notes |
|---|---|---|
| `id` | `text` PK | e.g. `uke-0001`. Auto-assigned on insert (see below) |
| `brand` | `text` not null | |
| `name` | `text` not null | |
| `volume` | `text` null | some products have none (Kent range) |
| `price` | `numeric(10,2)` not null | the ONLY source of price |
| `old_price` | `numeric(10,2)` null | null = not on sale |
| `sku` | `text` null | Kent range only |
| `image` | `text` not null | URL or `images/products/…` |
| `categories` | `text[]` not null | at least one of the 9 known categories |
| `tag` | `text` null | badge; null = no badge |
| `in_stock` | `boolean` not null default true | |
| `is_new` | `boolean` not null default false | maps to JSON `new` |
| `date_added` | `date` null | |
| `created_at` | `timestamptz` default now() | |
| `updated_at` | `timestamptz` default now() | trigger keeps it current |

**Client field mapping** (DB → renderer): `old_price`→`oldPrice`,
`is_new`→`new`, `in_stock`→`inStock`; the rest are identical.

**Id assignment on insert:** a `BEFORE INSERT` trigger assigns
`uke-%04d` from a dedicated sequence when `id` is null, so admins never type it
and ids stay collision-free. Existing ids (from migration) are preserved.

### `public.admins`

| Column | Type | Notes |
|---|---|---|
| `user_id` | `uuid` PK → `auth.users(id)` on delete cascade | |
| `email` | `text` | convenience copy for readability |
| `created_at` | `timestamptz` default now() | |

Populated **only** via the Supabase dashboard / service role — never from the
browser.

### `public.is_admin()`

`SECURITY DEFINER` function returning `boolean`:
`exists (select 1 from public.admins where user_id = auth.uid())`.
Used by RLS policies and exposed as an RPC so the client can decide whether to
render the admin bar (UX only — real enforcement is RLS).

## Security (RLS)

**`products`** (RLS enabled):
- `SELECT`: allowed for `anon` and `authenticated` (public shop is world-readable).
- `INSERT` / `UPDATE` / `DELETE`: allowed only when `public.is_admin()` is true.

**`admins`** (RLS enabled):
- `SELECT`: only rows where `user_id = auth.uid()` (a user can see their own row),
  or admins can see all. No client `INSERT`/`UPDATE`/`DELETE`.

**Keys:** the anon key is embedded in the static client (its designed purpose;
RLS protects writes). The service-role key is never in the browser, never logged.

## Auth flow (magic link on a static site)

1. supabase-js loaded from CDN; client created with `NEXT_PUBLIC`-equivalent
   project URL + anon key held in a small `js/supabase-config.js`.
2. **Staff login**: a lightweight login view (modal or `login.html`) — admin
   enters email → `signInWithOtp({ email })` → "check your inbox" → clicking the
   emailed link returns to the site with a session (persisted by supabase-js in
   localStorage).
3. On every page load, supabase-js restores any session. If a session exists,
   the client calls the `is_admin()` RPC. If true → render the **admin bar**.
   If false / no session → the page is exactly the normal read-only site.
4. Redirect URL for the magic link must be allow-listed in Supabase Auth settings
   (the site's Netlify URL + `http://localhost:3000` for dev).

**Seeding an admin (invite-only):** the admin signs in once via magic link to
create their `auth.users` row (or you invite them in the dashboard), then you
insert their `user_id` into `public.admins`. Only then does editing unlock.

## Public read switch

`Catalogue.load()` changes from `fetch('data/products.json')` to a supabase-js
query: `supabase.from('products').select('*')`, then map each row to the
renderer's shape. Everything downstream (category grids, featured strips, counts,
new-strip, cart re-pricing) is unchanged because they all consume `Catalogue`.
The existing error fallback (`showError`) stays for when Supabase is unreachable.

`data/products.json` and `npm run build:catalogue` are no longer on the live read
path. They are kept as an offline backup/export for now (not deleted), but the
site no longer reads the file.

## Inline editor

- Reuse the card markup from `render-products.js`. Cards already carry
  `data-product-id`; the editor locates the row by that id.
- **Admin bar** (only when `is_admin()`): `Edit mode` toggle · `＋ New product` ·
  `Log out`.
- **Edit mode on** → clicking a card opens an inline form (popover/drawer) with
  every field. **Save** → `supabase.from('products').update(...)` → update the
  `Catalogue` cache → re-render that card in place.
- **＋ New product** → same form, empty → `insert(...)` (id auto-assigned) →
  appears in its categories.
- **Delete** → button in the form, with a confirm dialog. Deleting an id that a
  featured list references is safe: `render-products.js` already logs and skips
  unknown featured ids.
- The editor overlay code lives in a new `js/admin-editor.js` (kept separate from
  the public renderer). It loads on all pages but stays dormant until an admin
  session is confirmed.

## Migration (one-time)

A Node script (`scripts/migrate-to-supabase.mjs`) reads all `data/products/*.json`
and upserts them into `public.products` (mapping `oldPrice`→`old_price`,
`new`→`is_new`, `inStock`→`in_stock`), preserving existing ids. Run once against
the restored project. Verify: row count = 868; spot-check a handful of fields.

## Files touched (anticipated)

- **New:** `js/supabase-config.js`, `js/admin-editor.js`,
  `scripts/migrate-to-supabase.mjs`, Supabase migration SQL.
- **Changed:** `js/render-products.js` (`Catalogue.load` reads Supabase);
  each HTML page (add supabase-js CDN + config + admin-editor scripts, and the
  login entry point); `CLAUDE.md` (document new architecture; mark Decap
  deprecated).
- **Unchanged:** `data/products/*.json` (kept as backup), featured JSONs,
  `data/settings.json`, `admin/` (Decap, deprecated).

## Testing / acceptance

- **RLS:** with the anon key, `SELECT` on products succeeds; `INSERT`/`UPDATE`/
  `DELETE` are rejected. As an admin session, writes succeed.
- **Public:** a fresh visitor sees the normal shop; no admin bar; products load
  from Supabase.
- **Admin:** magic-link login shows the admin bar; edit a price → it persists and
  appears on shop, the matching category page, and any home/featured strip that
  shows that product after refresh.
- **Add/Delete:** a new product appears in its category; a deleted product
  disappears and does not break featured strips.
- **Migration:** 868 rows present with correct field mapping.

## CLAUDE.md impact

This introduces a new live-editing architecture (Supabase DB + Supabase Auth +
client-side RLS-enforced writes) that supersedes the documented GitHub-publish /
Decap model for live editing. `CLAUDE.md` will be updated to describe the Supabase
model and to mark the Decap CMS path deprecated. The security *intent* is
preserved and strengthened: only admins can write (RLS), edits are bounded to the
`products` table, and no secrets reach the browser.

# Live Product CMS — Design Spec

**Date:** 2026-07-09
**Project:** UK Emporium redesign (Cape Town grocery/import catalog)
**Author:** TT8Vision

## Goal

Let the client make **live changes to products** — price, adding/editing/removing
products, stock availability, and flagging "New in store" items — through a
friendly `/admin` panel, with **no code and no developer in the loop**.

Today every product is hand-typed HTML across `index.html` + 9 `cat-*.html`
pages (~880 products, generated by `generate-categories.py` /
`generate-remaining.py`). Editing a price means editing HTML. This spec replaces
that with a single data source the client edits through a form UI.

## Scope

**In scope**
- Products become data-driven: one JSON source of truth, rendered client-side.
- Decap CMS admin at `/admin` for editing products (price, name, brand, volume,
  image, category, stock, tags).
- Stock states drive the UI (Out of stock → badge + disabled Add to cart).
- "New in store" toggle → homepage strip + "New" badge.
- Editable site text (hero copy, delivery thresholds, ticker) via a second small
  collection.
- One-time seed: extract existing HTML products into `products.json` so nothing
  is lost. Retire the Python generators.

**Out of scope (parked — "confirm cart later")**
- Cart → email enquiry / quote (Netlify Forms). The existing localStorage cart
  keeps working unchanged for now; the email hand-off is a later phase.
- Online payments (not happening — enquiry-by-email model).

## Constraints (from CLAUDE.md)

- HTML5 + Tailwind CDN + vanilla JS. **No build tools, no npm, no bundler, no
  framework.** Must run under Live Server / static hosting.
- Hosted on **Netlify** (site id in `.netlify/state.json`), deployed from git.
- New third-party deps allowed here (approved in brainstorming): **Decap CMS**
  (CDN) + **GitHub OAuth** for admin login.

## Architecture

Data-driven, fully client-side rendering — no build step. Decap CMS commits data
files to git; Netlify redeploys the static files (~1 min); pages fetch the data
at load and render.

```
┌─────────────┐   edits    ┌──────────────┐  commit   ┌─────────┐
│  Client     │──────────▶│ /admin       │──────────▶│  Git    │
│ (browser)   │  forms     │ (Decap CMS)  │  JSON      │  repo   │
└─────────────┘            └──────────────┘            └────┬────┘
                                                            │ Netlify redeploy (~1 min)
                                                            ▼
┌─────────────┐  fetch()   ┌──────────────────────────────────────┐
│  Shoppers   │◀──────────│ data/products.json + data/site.json    │
│ (browser)   │  render    │ rendered by render-products.js         │
└─────────────┘            └──────────────────────────────────────┘
```

### Components

1. **`data/products.json`** — single source of truth. Array of product objects:
   ```json
   {
     "id": "astonish-bathroom-cleaner",
     "name": "Bathroom Cleaner",
     "brand": "Astonish",
     "volume": "750ml",
     "category": "cleaning",
     "price": 39.90,
     "oldPrice": null,
     "stock": "in-stock",          // in-stock | low-stock | out-of-stock
     "tag": "popular",             // none | bestseller | popular | specialty | sale
     "isNew": false,               // "New in store"
     "image": "images/products/astonish-bathroom.png",
     "order": 12
   }
   ```
   `category` matches the `cat-*.html` slug (beers, cereals, cleaning,
   colddrinks, confectionery, groceries, hotdrinks, kent, personalcare).

2. **`data/site.json`** — editable text: hero headline/subcopy, ticker lines,
   delivery threshold (`freeDeliveryOver`, `flatFee`, `radiusKm`). Renderer swaps
   these into the relevant pages so copy edits don't need code.

3. **`render-products.js`** (vanilla JS, loaded on every catalog page) —
   - `fetch('data/products.json')` once, cache in memory.
   - On a category page, filter by that page's `category` and render cards into
     the existing grid container, reusing the current `.product-card` markup/CSS.
   - On `index.html`, render the featured strip and a **"New in store"** strip
     (`products.filter(p => p.isNew)`).
   - Stock rules: `out-of-stock` → "Out of stock" badge + `disabled` Add-to-cart;
     `low-stock` → "Low stock" badge, still purchasable.
   - Price/oldPrice formatting reused from current design (R, tabular nums).

4. **`/admin/index.html` + `/admin/config.yml`** — Decap CMS from CDN. Two
   collections:
   - **Products** (`data/products.json`, list widget) — fields map 1:1 to the
     product object; `stock` and `tag` are `select` dropdowns; `isNew` a boolean;
     `image` uses the media library (uploads land in `images/products/`).
   - **Site text** (`data/site.json`, single file) — the editable copy fields.
   - `backend: github` with GitHub OAuth; media folder `images/products`.

5. **Auth** — GitHub OAuth app + an OAuth handler so `/admin` can "Log in with
   GitHub." Client uses a single GitHub login controlled by TT8Vision; they only
   ever see the Decap forms, never the repo. (Exact OAuth relay — Netlify
   function vs. hosted relay — chosen at implementation; no build step either
   way.)

### One-time data seed

A **throwaway** Node/Python script parses the existing `cat-*.html` product cards
(name, brand, volume, price, old price, tag, image `src`) into `data/products.json`,
assigning `category` from the filename and `stock: "in-stock"` by default. Run
once, verify counts (~880) against `grep -c product-card`, then commit. After
that the HTML product grids are replaced by empty containers the renderer fills.

### Migration of existing pages

For each of the 9 `cat-*.html` + `index.html`:
- Replace the hardcoded `.product-card` blocks with an empty grid container
  (`<div id="product-grid" data-category="cleaning"></div>`) and a `<script src="render-products.js">`.
- Keep all layout, headers, filters, and styling intact.
- Retire `generate-categories.py` / `generate-remaining.py` (superseded).

## Data flow (edit a price)

1. Client opens `yoursite.com/admin`, logs in with GitHub.
2. Edits price on "Bathroom Cleaner", clicks **Publish**.
3. Decap commits `data/products.json` to git.
4. Netlify detects the commit, redeploys static files (~1 min).
5. Shopper loads any page → `render-products.js` fetches the new JSON → new price
   shows everywhere the product appears.

## Error handling / edge cases

- **`products.json` fails to load** → renderer shows a friendly "Products
  temporarily unavailable" message in the grid, logs to console; page chrome
  still renders.
- **Missing image** → fallback placeholder image; never a broken `<img>`.
- **Out of stock** → badge + disabled Add-to-cart; if an out-of-stock item is
  already in the cart, it's flagged at cart view (cart logic touched minimally
  now, full treatment in the parked cart phase).
- **Bad/empty field** (e.g. no price) → renderer skips price display gracefully;
  Decap config marks required fields to prevent this at edit time.
- **Cache** — fetch with a cache-busting query or rely on Netlify's deploy
  invalidation so clients don't see stale JSON after a publish.

## Testing / verification

- Seed script: assert product count per category matches `grep -c product-card`
  on the original HTML before deleting anything.
- Render: load each category page locally (Live Server) and confirm the grid
  matches the pre-migration page visually and in count.
- Stock: set one product to each stock state and confirm badge + button behavior.
- New: toggle `isNew` and confirm it appears in the homepage "New in store" strip.
- Admin: run Decap locally (`local_backend`) to confirm forms edit the JSON
  before wiring live GitHub OAuth.

## Open items (decide at implementation, not blocking)

- OAuth relay mechanism (Netlify function vs. hosted OAuth provider).
- Whether `site.json` text editing ships in phase 1 or follows products.
- Cache-busting strategy specifics.

## Phasing

- **Phase 1 (this spec):** data model + seed + render migration + Decap products
  admin + GitHub login. Client can edit price/products/stock/New live.
- **Phase 2 (parked):** cart → email enquiry via Netlify Forms.
